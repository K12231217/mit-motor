# 这块板交给"任意 agent"能不能做完毕设？

> 结论先说：**不能。** 不是 agent 的能力问题，是**接口与证据的形态问题**。
> 现在的产物是"一块板 + 一份论文方案 + 一份需求表"；agent 需要的却是
> **机器可读的板级事实、可执行的 bring-up 阶梯、可判定的验收数据**。
> 缺这三样，agent 会稳定地产出"看起来收敛、其实错"的结果——比不干活更糟。

## 1. 按"第一次上手会先撞上什么"排序的失败点

| # | 现象（agent 会先看到）| 真实原因 | 它会怎么误判 | 需要补什么 |
|---|---|---|---|---|
| 1 | 电流三路恒为 0 或恒定偏移 | ADC 触发链有 ~10 个必须同时对的旋钮：TIM1 `MMS2/CR2` 选 TRGO2、ADC `CFGR.EXTSEL/EXTEN`、注入 vs 规则组、`SMPR` 采样时间、ADC 时钟 42.5 MHz、`ADCAL` 上电校准、DMA 循环与半传输、OPAMP `OPAINTOEN` + 选对**内部**通道 | "板子坏了/SOx 没焊" | bring-up 自检（§2.A）逐级 PASS/FAIL，把"哪一级绿了"变成可读状态 |
| 2 | 读数有值但和实际电流差 10 倍、或方向反 | 三路 SOx 走的是 OPAMP 内部跟随器，ADC 要选 OPAMP 的**内部通道**而不是引脚本身的 `ADCx_INy`；相序、编码器方向、LS/HS 极性都可能反 | "增益标定算法不收敛" | 板级清单里写死"引脚→OPAMP→ADC 内部通道"三元组；加极性与相序自检 |
| 3 | 6 路 PWM 一使能就炸管 | MP6540HA 是 HS/LS 六输入、**无内部死区**；`BDTR` 的 `DTG/MOE/OSSI/OSSR/LOCK` 或 `CCER` 极性错一个就是直通 | 无法从现象反推（芯片已死）| 安全阶梯（§2.F）+ 死区实测项 + 上电默认全低 |
| 4 | 校准"收敛"了，但换个电流点就错 | 采样窗口无效时数据也进了估计器（低边未同时导通、ADC 在死区里采样）；零和约束下**任何样本都能解出一组增益**（残差恒零）| "方法有效，已收敛" | 窗口有效性必须由固件计数器判定（§2.A S4），并把无效样本比例写进验收 |
| 5 | 没有真值，无法判断对错 | 10 mΩ 分流 + DMM / INA240 是**外部夹具**；没有它，绝对刻度无从谈起，相对增益也只能自证 | "标定结果自洽即可" | 夹具清单 + 记录 CSV schema（§2.E）|
| 6 | 实验做到一半保护动作，数据断 | nFAULT/OVP/BKIN 的锁存与清除策略没实现，或阈值没落到代码里 | "是噪声/偶发" | 故障码 + 锁存状态进状态字；故障前后 N 个样本的黑匣子（HR-814）|
| 7 | 换一块板结论不一致 | 每块板的零位码、增益比、编码器零偏、OVP 翻转点都不同，没有"每板标定档案" | "算法不鲁棒" | 标定档案格式 + 版本 + CRC，存 flash（§2.G）|
| 8 | 两个 agent 各写一套，互相不认 | 还没有 ICD：CAN 帧布局、trace 记录格式、USB 命令集、标定文件 schema 都没定 | 各写各的，实验不可复现 | `motor-icd` 先落地 v0（§2.C）|

## 2. 需要补的七类东西（按性价比排序）

### A. Bring-up 阶梯 + 自检固件（最高优先）

一个 `self_test` 子命令，每级输出 `PASS/FAIL + 数值`，通过 RTT/USB 读出：

| 级 | 检查 | 判据（机器可判）|
|---|---|---|
| S0 | 时钟/Flash/RAM/唯一 ID | 170 MHz、512 K 可读、RAM 写读一致 |
| S1 | GPIO/EXTI 回环 | 输出→输入回环计数一致 |
| S2 | ADC 通道与量程 | PA4 DAC 斜坡进 J_SYNC，三路读数偏差 ≤ 2 LSB、线性 R² > 0.999 |
| S3 | ADC 同步性 | 扫触发相位，三路跳变点的相位差 = 偏斜（写入记录）|
| S4 | PWM 六路 + 死区 | LA/DWT 测得死区与设定差 < 10 %；互补无重叠 |
| S5 | SOx 静态零位 | 三路零位码 = 2048 ± 30（VREF/2 理论值）|
| S6 | 编码器 | 转 1 圈，E1 计数变化与分辨率一致；E2 与 E1 的齿比关系 |
| S7 | CAN 回环 | 自发自收，2 Mbit/s 24 h 零错帧 |
| S8 | 故障链 | 人为拉低 nFAULT / 抬母线，锁存 + 状态字可读 |

**为什么这是最高优先**：它把"agent 有没有做对"从"人看波形"变成"读一个 PASS 位"。没有它，前 8 个失败点里至少 5 个无法自证。

### B. 机器可读的板级清单（board manifest）

一个 `board.yaml`，把现在散落在 `hardware-requirements.md` 与原理图里的知识变成可查询事实：

```yaml
mcu: STM32G474RET6
net_divider: { r_series: 100, c_to_gnd: 100p, r_up: 4.99k, r_down: 4.99k, rth: 2.495k }
sox: { ratio_a_per_amp: 1/9200, volts_per_amp: 0.2712, zero_volts: VREF/2 }
pins:
  - { net: SOA, pin: PA1, adc: {unit: 1, in: 2}, opamp: {n: 1, mode: follower, adc_chan: <按 RM0440 填>}, comp: COMP1_INP, tp: TP_SOA }
  - { net: PWM_AL, pin: PB13, timer: {tim: 1, ch: 1, n: true} }
inject:
  gain: { method: parallel, r: 47k, delta_gain: -0.095, zero_shift: 0 }
  offset: { method: parallel, r: 18k, delta_amps: +0.74, gain_coupling: -0.12 }
limits: { vbus_max: 28.0, ovp_trip: 28.1, phase_amps: 5.0, d_max: 0.90 }
```

**为什么必须有**：这份仓库刚刚就发生过一次"人拿着网表把 MP6540HA 读成 PWM+EN"的错误，代价是潜在的直通炸板。agent 读 Markdown 会犯同样的错，而且更自信。

### C. ICD v0（`motor-icd`）

- CAN：命令帧/反馈帧/故障帧的 ID、字节布局、超时与主权切换；
- trace：一个样本 = `{t_us, raw[3], ext_ref, dq, state, flags}` 的二进制布局（定长 24~32 B）；
- USB：命令集 + 流控（1 kHz 遥测 + 突发 trace）；
- 标定文件：`{board_id, magic, version, crc, zero[3], gain[3], enc_off[2], ovp_mv}`。

没有 v0，agent 之间、以及"今天的 agent 和三个月后的 agent"之间无法对齐数据。

### D. 主机侧 golden data + 回放（`tools/replay`）

- 录一段"已知电流 + 三路 raw + 外部真值"的数据集（10 秒足够）；
- 给 `motor-core` 的单元测试用固定向量（Clarke/Park、RLS 一步、零位拟合）；
- 回放工具输出与录制的期望值 diff。

**作用**：estimator 的开发可以完全不碰硬件；等硬件到了，只验证"接上了没"。这也是把"agent 能不能做"变成"能不能在 x86 上先做完"。

### E. 可执行的实验协议 E1–E10

每条要写到"另一个人照做能得到同样数字"：

- 接线（哪根线串分流、哪根接示波器 CH1/CH2）；
- 仪器设置（20 mV/div、触发沿、LA 采样率）；
- 判据（数值区间，而不是"看波形正常"）；
- 记录表（CSV 列名固定，直接喂回放工具）。

现在 HR 文档里 E1–E10 有判据、没有接线步骤与仪器设置。

### F. 安全阶梯与软件互锁

- 上电默认：六路输入全低、nSLEEP 低、MOE=0；只有自检 S0–S5 全 PASS 才允许使能；
- 软件限流 + `d_max` 硬夹紧 + 母线过压/欠压门限进代码；
- 故障一律锁存，清除需要显式命令 + 无故障持续 T；
- 看门狗：通信中断 > 20 ms 自动停机。

### G. 每板标定档案

出厂/首次上电标定后写 flash：`board_id`（用 96-bit UID）、零位码、增益比、编码器零偏、OVP 实测点、版本 + CRC。
换板后所有实验结论都要带 `board_id`，否则不可复现。

## 3. agent 能做 / 不能做的边界

| 能做（补齐上述之后）| 不能做（永远需要人）|
|---|---|
| 写 FOC/标定/状态机代码并在 x86 上测 | 判定"这个风险可接受"（如 d_max 取 0.9 还是 0.95）|
| 跑自检、读状态字、按协议做实验、填记录表 | 搭建/接线夹具、确认物理安全 |
| 用回放数据调估计器、做消融对比 | 提供外部电流真值的"信任"（仪器校准、测量不确定度）|
| 生成图表与论文草稿 | 决定论文边界与叙事（哪些结论可以宣称）|

## 4. 如果只想先做三件事

1. **`board.yaml`**（半天）：把引脚/模拟链/注入系数写成事实表，杜绝"读错料号"类错误。
2. **`self_test` 的 S0–S5**（两三天）：让"板子是否可用"变成 6 个 PASS 位。
3. **ICD v0 + 回放数据集**（两三天）：让算法开发脱离硬件，且结论可复现。

这三件做完，agent 才能在"不炸板、不瞎猜"的前提下推进；其余（E/F/G）是让它跑得久、结论能进论文。
